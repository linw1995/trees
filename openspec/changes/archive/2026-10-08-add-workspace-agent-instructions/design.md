# Design

## Decisions

- Keep the static English template beside its filesystem implementation and
  explicitly include it in the Nix package source. Limit it to the workspace
  layout and five core rules; retain lifecycle details in the user documentation.
- Share creation, recognition, removal, and filename validation through one
  implementation module. Use typed Snafu errors and transparent propagation.
  Retain the existing module entry points and visibility conventions.
- Create files exclusively, preserving existing entries. Recognize only ordinary
  files with the exact generated bytes. The size check bounds file reads;
  symlink metadata avoids granting an exemption to links.
- Create instructions before provisioning worktrees and remove them during
  creation rollback. Addition recovery restores missing instructions before
  publishing a completed layout. Reuse restores older missing files.
- A failed root directory creation grants no container ownership. Classify that
  existing filesystem error before rollback, preserving the original error and
  user-visible message while leaving existing content untouched.

## Ablation Review

| Experiment | Observed result | Decision |
| --- | --- | --- |
| Remove the acquisition instruction journal step | Focused regressions pass; recovery does not consume this step. | Remove the extra database write. |
| Overwrite existing instructions | The file preservation regression fails. | Retain exclusive creation. |
| Ignore instruction content equality | A same-length modified file is incorrectly accepted and removed. | Retain exact byte comparison. |
| Follow instruction symlinks | A link to matching content is incorrectly accepted. | Retain symlink metadata. |
| Omit removal of generated instructions during GC | GC fails to remove the shared root. | Retain removal. |
| Remove reserved-name validation from naming and addition planning separately | Both admission regressions fail. | Retain collision admission checks. |
| Remove the generated-file exemption from root validation | Generated instructions are rejected as unexpected content. | Retain the shared validator exemption. |
| Remove the failed-container ownership guard | Existing instructions disappear. | Retain the review fix. |
| Skip addition rollback cleanup | The existing journal-fault regression fails. | Retain compensation cleanup. |
| Omit generated-file removal during creation rollback | The existing partial-creation regression leaves the shared root behind. | Retain creation cleanup. |
| Skip completed-addition recovery generation | Recovery publishes a layout without instructions. | Retain recovery preparation. |
| Replace standalone manual and symlink lifecycle tests with existing creation and file-validation assertions | Focused regressions pass and still detect content, overwrite, and symlink omissions. | Retain the smaller tests. |

## Review and Validation

The review checks typed errors, unchanged visibility conventions, claim
preservation, existing-file protection, root-worktree behavior, rollback,
interrupted additions, and package inclusion. All 433 Rust tests, repository
hooks, and strict OpenSpec change validation passed before archive. Twelve code
ablation experiments identified one removable journal step and eleven
behavioral omissions detected by the retained regressions.

The existing synchronized specifications have fourteen requirement-length
warnings in `workspace-reuse` and ten in `workspace-management` under strict
validation. After archive, standard specification validation passes and strict
diagnostics match this baseline exactly.

## Trade-Offs

Recognition is intentionally limited to the current generated bytes. Modified
or older differing templates retain the normal unexpected-content protection.
No template migration or user-file replacement policy is introduced.
