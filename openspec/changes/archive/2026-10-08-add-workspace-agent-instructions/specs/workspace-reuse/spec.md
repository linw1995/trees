## ADDED Requirements

### Requirement: Recognize Generated Workspace Instructions

Trees SHALL recognize shared instructions as managed content only when
`AGENTS.md` is a regular file whose bytes exactly match the generated template.
Modified files, directories, symlinks, and unreadable entries SHALL NOT receive
the generated-file exemption from normal shared-content protection.

#### Scenario: Accept Unchanged Generated Instructions

- **WHEN** a shared root contains the unchanged generated instruction file
- **THEN** that file does not prevent release, automatic reuse, or normal removal

#### Scenario: Reject a Same-Length Modification

- **WHEN** an instruction file's contents change without changing its length
- **THEN** Trees treats the file as unexpected content and preserves it during normal workspace access and removal

#### Scenario: Reject Matching Content Through a Symlink

- **WHEN** `AGENTS.md` is a symlink to a file containing the generated bytes
- **THEN** the link remains unexpected content and its target is preserved

### Requirement: Clean up Generated Instructions Safely

Workspace cleanup and rollback SHALL remove recognized generated instructions
from owned shared containers before removing those containers. Normal cleanup
SHALL retain unexpected-content protection for modified files and links.
A failed shared-container creation SHALL NOT remove the existing container
or its instructions.

#### Scenario: Remove a Clean Shared Workspace

- **WHEN** normal removal or GC removes clean child worktrees and their generated instructions
- **THEN** it also removes the shared container without requiring force

#### Scenario: Roll Back an Addition

- **WHEN** addition rollback restores the original root worktree after creating shared instructions
- **THEN** it removes only the recognized generated instructions before removing the owned container

#### Scenario: Preserve a Container Created After Planning

- **WHEN** an existing shared container makes directory creation fail
- **THEN** rollback preserves that container and its instructions, even when they match the template

## MODIFIED Requirements

### Requirement: Check Shared Workspace Content Before Reuse

A shared workspace root SHALL contain only persisted managed worktree paths
and recognized generated instructions before release or automatic reuse.
Unexpected content or unreadable roots SHALL prevent reuse. Reconciliation
SHALL mark an otherwise attached workspace `degraded` when this check fails and
restore `ready` after content removal. A root that is itself a managed worktree
SHALL continue to use the existing Git cleanliness predicate.

#### Scenario: Observe Unexpected Shared Content

- **WHEN** otherwise attached worktrees share a root containing extra files, directories, or symlinks, including `public/` or an empty directory
- **THEN** reconciliation marks the workspace degraded while keeping its clean worktrees attached

#### Scenario: Restore Eligibility After Reconciliation

- **WHEN** shared content is removed and reconciliation observes otherwise reusable managed worktrees
- **THEN** the workspace becomes ready and can be acquired again

#### Scenario: Allow a Managed Worktree Named Public

- **WHEN** the workspace root contains only persisted managed worktree paths, including a worktree named `public`
- **THEN** its name does not prevent release or automatic reuse

#### Scenario: Reject a Dangling Shared Symlink

- **WHEN** an unexpected root entry is a symlink whose target does not exist
- **THEN** root content validation rejects that entry without following its target

#### Scenario: Reject an Unreadable Root

- **WHEN** root content validation cannot read the shared workspace directory
- **THEN** the workspace does not satisfy the reusable snapshot predicate
