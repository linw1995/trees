# Multi-Worktree Workspace

This directory is a monorepo-style workspace composed of multiple independent
Git worktrees managed by Trees. The shared root is not a Git repository; each
repository lives in its own child directory and has its own history and branches.

## Working in the Workspace

- Run Git commands inside the relevant worktree, or use `git -C <repo> ...`.
  Commit changes separately in each repository.
- Read and follow each repository's `AGENTS.md` and any more specific instructions
  before editing files in that repository.
- Worktrees start with a detached HEAD. Create a named branch before committing,
  or attach a branch to completed commits before release, so the work remains
  reachable when Trees resets or removes the worktree.
- Use Trees to manage workspace membership and removal. Do not initialize a Git
  repository at the shared root or manually rearrange its directories.

## Keeping the Workspace Clean for Reuse and Cleanup

- Keep the shared root limited to managed worktree directories and this generated
  `AGENTS.md`. Do not edit this file or store notes, logs, scratch files, build
  output, or extra directories at the shared root.
- Put temporary files and artifacts outside the workspace, such as in a directory
  created by `mktemp -d`. Keep repository changes inside the relevant worktree.
- Before finishing, inspect every worktree with
  `git -C <repo> status --porcelain=v1 --untracked-files=all`. Save your changes
  on a named branch or outside the workspace, and remove only disposable files
  you created. Do not discard someone else's changes to make a worktree clean.
- Ignored files do not appear in that status output. Inspect them with
  `git -C <repo> status --short --ignored`; keep valuable files outside the
  workspace and remove disposable generated output before cleanup. Ignored files
  can block normal worktree removal or checkout during reuse.
- Run `trees status --view workspaces` to inspect workspace health. When finished
  with an automatic workspace, run `trees release` from its root or a worktree.
  An active claim persists after the shell exits and prevents automatic GC.
- Release requires all worktrees to be clean and the shared root to contain no
  unexpected content. It aligns worktrees to the source repositories' selected
  revisions in detached mode, so preserve commits on named branches first.
  Trees recognizes this unchanged generated file and removes it during cleanup.
- If release or cleanup fails, resolve the reported problem while preserving
  valuable work. Do not use forced removal or destructive Git cleanup as a
  shortcut to a clean workspace.
